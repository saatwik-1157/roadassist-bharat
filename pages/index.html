The AI question, answered first

“AI-powered” is the claim most worth distrusting, so here is the whole of it. Two components, and neither is a language model:

ComponentWhat it actually isEvidence
RAKSHA road-damage detection A YOLO11 model trained in this repository on RDD2022 across four countries mAP50 0.471, mAP50-95 0.226 on held-out validation
Roadside diagnosis A deterministic rule table (ADR-0006) returning rules-1.0.0 Labelled as a rules engine on every screen that shows it

No language model is involved anywhere — no LLM dependency in any manifest, no chat endpoint called from any source file. That is enforced rather than promised: npm run no-llm fails the build if one ever appears, and it runs in CI.

The decisions worth defending

A model is never allowed to dispatch

ADR-0005. A crash signal raises an incident that waits in AWAITING_CONFIRMATION until a person moves it. A false positive that dispatches is worse than a false negative that asks. ADR-0011 then bounds the mirror failure — nobody arriving — with a review deadline per severity that escalates attention, never responders.

Exactly one channel owns an emergency

The SOS ladder falls back data → SMS → 112 → offline queue. A confirmed SMS must not also queue an API replay; an unconfirmed one must. Getting this wrong sends two responders to one accident, or none.

Races are settled by Postgres, not by timing

Row locks with SELECT … FOR UPDATE, a partial unique index so “paid once” holds when two confirmations arrive together, and a hash-chained audit log that Postgres RULES make append-only.

The build refuses to let the documents lie

Five gates run on every push: documented claims must match the measured file, every file.ts:123 citation must still point at real code, module boundaries hold, no language model enters the system, and no personal data leaves India. That last one found a live leak the day it was written.

Run the real thing, one command

Nothing to install but Docker. This is the whole platform, not a mock:

git clone https://github.com/saatwik-1157/roadassist-bharat
cd roadassist-bharat
docker compose -f docker-compose.demo.yml up

Then open http://localhost:4000. It pulls the published image, brings up PostGIS, migrates, seeds, and serves the citizen app, mechanic console, authority dashboard and live map from one process. Running it twice is a no-op rather than an error.

Sign in with +917000000000 (citizen), +919999900001 (authority) or +919600000000 (mechanic). The one-time code is returned by the API in demo mode and fills itself in.

Deliberately not built

Said plainly rather than implied otherwise: iOS, Android Auto, IVR, USSD, satellite, mesh networking, ERSS-112 handoff (stubbed, and the API says so in its own response), Kubernetes, Terraform, autoscaling and multi-zone anything. There is no load test — latency is measured single-user, on one machine.
